# Repository Structure

Author: Shuvam Banerji Seal

## Top-level layout

- `en_BDNews24/` - raw BDNews24 source corpus
- `en_TheTelegraph_2001-2010/` - raw Telegraph source corpus
- `data/archives/` - original `.tgz` source archives
- `data/fire2012/adhoc/topics/` - FIRE 2012 ADHOC topic/query files
- `data/fire2012/adhoc/qrels/` - FIRE 2012 ADHOC qrels (v1/v2)
- `notebooks/` - analysis notebooks
- `scripts/` - utility, integrity-check, indexing, and retrieval scripts
- `reports/` - text reports generated by analysis pipeline
- `outputs/` - generated machine-readable artifacts
- `docs/` - project documentation and reference notes

## Outputs

- `outputs/analysis/` - CSV and analysis tables
- `outputs/jsonl/` - combined JSONL datasets
- `outputs/repaired_xml/` - repaired XML corpora
- `outputs/indexes/` - PyLucene index files
- `outputs/runs/` - retrieval run files (`.tsv`)

## Reproducibility flow

1. Run notebook in `notebooks/` for analysis + repair + export.
2. Validate combined datasets with `scripts/check_jsonl_integrity.py`.
3. Use `scripts/check_jsonl_integrity_progress.py` for long-running checks with progress logs.
